特殊カードパス — 3種の例外処理

▼
SPECIAL_CARD_IDS — 一括処理パス
K004 K010 K011
getCardEffectSteps() によるステップ分解をスキップし、playCard() を1回呼ぶだけで完結する。

理由: これらのカードは複数ステップのアニメーション分解に対応していない特殊な効果を持つため、 レガシーな単一呼び出しパスを維持している。
P018「受け流し」— モーダル選択パス
P018
通常のカードプレイの代わりに CardChoiceModal を表示し、プレイヤーにバリアントを選ばせる。

フロー: handleCardClick → setPendingHandIndex → modal表示 → handleCardChoice → 手札内のP018をchosenCardに置換 → playCard() → 捨て札でP018に差し替え

これにより「受け流し」の選択バリアントが永続しない（次戦でもP018として扱われる）。
楽観的UI更新パターン
標準パスでは、エネルギーと手札の変更をアニメーションループ開始前に即時反映（楽観的更新）。

これによりユーザーは操作後すぐにエネルギー消費・手札変化を視認でき、 300ms × ステップ数の待機中も UIがフリーズしていないように見える。
isAnimating — 入力ロック設計
async ハンドラー開始時に setIsAnimating(true)、完了時に false。

handleCardClick 先頭と CardArea に両方で isAnimating チェックをすることで、 アニメーション中の多重クリック・ターン終了を二重に防ぐ設計。
